## Cambios realizados

Se revisaron el repositorio y los comentarios del profesor sobre la Entrega 1. Se cambiaron los endpoints del servicio Java a Jakarta REST con Jersey. Se mantuvieron las operaciones existentes, incluida la opción de borrar clientes, y se corrigieron las respuestas para datos incompletos o identificadores inexistentes.

Se preparó el TO-BE con los tipos de tarea y el inicio por mensaje, y se probó en Flowable 8. El worker consultó Java, creó un registro y cambió su estado cuando se registró la compra.

Se usaron dos bases H2 en archivos separados, una para Flowable y otra para los clientes. Se reiniciaron los servicios para comprobar que los datos siguieran guardados.

## Pruebas realizadas

- El servicio Java compiló y arrancó.
- Se pudo consultar, registrar, cambiar el estado y borrar un cliente de prueba.
- Los datos incompletos devolvieron un error 400 y los ID inexistentes un error 404.
- Un cliente nuevo completó el recorrido con compra.
- Un cliente que ya estaba registrado completó el recorrido sin compra y no se duplicó.
- Después del reinicio, el cliente y la tarea pendiente seguían disponibles y se pudo continuar el proceso.

Los resultados quedaron en Pruebas/Recorridos. También se actualizaron las instrucciones y el diagrama de arquitectura.
